# PC 端知识运营页

路径：`/dashboard/knowledge`

"人机协同"的核心模块，将已完成的工单沉淀为知识。知识库由外部平台（扣子）维护，此处仅负责生成并导出 CSV。

页面分成左右两栏：左侧为候选池列表，右侧为清洗好的 QA 对列表。

## 候选池

### 数据源逻辑

自动拉取满足以下条件的工单：
1. 工单状态 = 已完成
2. 预防措施字段不为空
3. 是否转化知识库 = False

### 列表样式

与 [工单中心页](工单中心页.md) 的数据表格样式一致，但忽略"状态"和"操作"列。最左侧增加"转化"按钮，点击后打开转化弹窗。

## 转化弹窗

左右布局：
- **左侧**：工单详情组件（展示模式，不显示操作按钮）
- **中间**：右箭头按钮，文案"AI 总结"。点击后调用 Kimi API 将工单内容总结为 QA 对，自动填入右侧表单
- **右侧**：表单，包含"问题"输入框和"回答"输入框，底部"保存"按钮

点击"保存"后关闭弹窗，将 QA 对添加到右侧列表，该工单从候选池前端暂时移除。

> 关于数据一致性：「保存」仅暂存前端状态，工单的 `是否转化知识库` 字段不会立即更新。用户点击「导出 CSV → 我已完成」后才写入数据库。刷新/关闭页面会导致未导出的 QA 对丢失——这是刻意的设计，Demo 阶段不实现草稿持久化。

## 清洗好的 QA 对列表

每个条目两行：第一行问题、第二行回答（超长文字截断不换行）。条目右侧：
- **编辑按钮**：打开转化弹窗重新编辑
- **删除按钮**：删除该行，将对应工单放回候选池

列表下方有"导出 CSV"按钮，点击后：
1. 前端将列表转化为 `question,answer` 表头的 CSV 文件并触发下载
2. 弹出告知弹窗，提醒用户前往扣子知识库上传该文件，弹窗有"我已完成"和"取消"按钮
3. 点击"我已完成"：将 QA 对对应的工单标记为"已转化"，清空 QA 列表，刷新候选池
4. 点击"取消"：仅关闭弹窗，不改数据
