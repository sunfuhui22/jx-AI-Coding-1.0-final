# 数据定义

> Demo 阶段仅实现以下必要字段，不需要完整数据。

## 实体列表

- **用户（profiles）** — 用户业务信息（关联 Supabase Auth）
- **项目（projects）** — 施工项目
- **用户身份（user_roles）** — 用户 × 项目 × 角色三元组
- **工单（tickets）** — 质检工单
- **工单变更记录（ticket_logs）** — 工单全生命周期变更记录

## 用户（profiles）

登录鉴权由 Supabase Auth 负责，本表仅存储用户业务信息。

| 字段名称 | 类型 | 说明 |
|----------|------|------|
| 用户ID | 自动（主键） | 全局主键 |
| 用户名称 | String | 名称 |
| 部门 | String | 用户所在部门 |
| 头像 | URL | 头像图片链接 |

权限：仅管理员可写；所有登录用户均可读。

## 项目（projects）

| 字段名称 | 类型 | 说明 |
|----------|------|------|
| 项目ID | 自动（主键） | 全局主键 |
| 项目名称 | String | 项目名称 |
| 项目城市 | String | 项目所在城市 |
| 客户名称 | String | 项目的客户公司名称 |
| 项目类型 | Enum | 地产项目 / 园区项目 / 景观项目 / 居住区项目 / 政府项目 |

权限：仅管理员可写；所有登录用户均可读。

## 用户身份（user_roles）

用户与项目的多对多关联表。

| 字段名称 | 类型 | 说明 |
|----------|------|------|
| 关联ID | 自动（主键） | 全局主键 |
| 用户 | 用户外键 | 关联用户 |
| 项目 | 项目外键 | 关联项目 |
| 角色 | Enum | 质检员 / 施工方 / 管理员 |

权限：仅管理员可写；所有登录用户均可读。

## 工单（tickets）

| 字段名称 | 类型 | 说明 |
|----------|------|------|
| 工单ID | 自动（主键） | 数据库自增，即工单编号 |
| 工单状态 | Enum | 待处理（默认）/ 已完成 / 已拒绝 |
| 严重程度 | Enum | 轻微 / 一般 / 严重 / 紧急 |
| 工单创建时间 | DateTime | 记录创建时间 |
| 工单发起人 | 用户外键 | 发起用户（质检员） |
| 工单所在项目 | 项目外键 | 工单关联的项目 |
| 当前责任人 | 用户外键 | 当前负责处理该工单的施工方 |
| 专业类型 | Enum | 建筑设计专业 / 结构专业 / 给排水专业 |
| 问题描述 | String | 问题简要描述 |
| 详细位置 | String | 楼栋-楼层-区域 |
| 图片 | Array\<URL\> | 支持多张 JPG，非必填 |
| 问题详情 | Text | 非必填 |
| 问题归因 | Text | 解决时必填 |
| 预防建议 | Text | 非必填 |
| 是否转化知识库 | Boolean | 是否被转化为知识库，默认否 |

权限：只能从后端 API 写，不可直接从浏览器调用 Supabase API 写。登录用户只可读取当前身份所在项目下的条目。

> 工单变更逻辑涉及复杂的状态流转校验和自动创建变更记录，统一在 Next.js 后端完成所有写操作，不使用 Supabase RLS + Database Function 混合方案。

## 工单变更记录（ticket_logs）

| 字段名称 | 类型 | 说明 |
|----------|------|------|
| 变更ID | 自动（主键） | 全局主键 |
| 工单 | 工单外键 | 被流转的工单 |
| 操作人 | 用户外键 | 操作流转的用户 |
| 操作 | Enum | 创建 / 解决 / 拒绝 / 指派他人 / 重新打开 / 编辑 |
| 字段diff | JSONB | 用 key-value 存储所有更新的字段值，不存储旧值 |
| 操作说明 | Text | 操作人在操作时选填的操作说明 |
| 时间 | DateTime | 操作时间 |

权限：只能从后端写。登录用户只可读取当前身份所在项目下的工单相关条目。
