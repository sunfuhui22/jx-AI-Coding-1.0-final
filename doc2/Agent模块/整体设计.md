# Agent 整体设计

## 架构总览

```
用户(多角色) ↔ 前端UI ↔ 主Agent ↔ 知识获取子Agent（外部API）+ 工单查询MCP + create_ticket tool_call(HITL) + 对话数据库
```

## 关键设计要点

- **单一身份**：用户登录时固定单一身份（项目+角色），不存在运行中多身份场景
- **多模态**：用户可带图片输入，主 Agent 需将图片信息纳入上下文
- **主 Agent 是唯一对话出口**：子 Agent 不直接与用户对话，只返回知识文本给主 Agent
- **知识子 Agent 多轮检索**：信息不足时自动追加查询，而非一次就返回
- **Human-In-The-Loop 工单创建**：Agent 不直接创建工单，通过 `create_ticket` tool_call 通知前端渲染工单卡片，用户确认补充后前端调用后端 API 完成创建

## 主 Agent 职责

接收用户输入，判断意图，调度子 Agent 或工具，与用户多轮对话直到任务完成。

### 上下文构成

- **System Prompt**（见 [system_prompt.txt](system_prompt.txt)）
- **对话历史**：包括工具调用等所有信息，按一问一答算仅保留最近 6 轮
- **当前用户输入**（文本 + 图片）

### 内部功能模块

- **智能意图识别** — 解析用户输入意图，按意图路由规则调度
- **多轮对话管理** — 维护对话状态，管理追问与上下文
- **工具调度** — 调用 queryTicket MCP 和 create_ticket tool_call
- **Stream 消息广播** — 向前端 UI 推送流式响应
- **外部知识库接入** — 调用知识获取子 Agent

## 意图路由规则

| 意图 | 判断依据 | 路由到 |
|------|----------|--------|
| 知识问答 | 用户询问施工规范、工艺标准、设计要求等知识性问题 | 调用知识子 Agent API |
| 工单查询 | 用户询问某个工单进度、状态，或提到工单编号 | 调用 [queryTicket MCP](工单查询MCP定义.md) |
| 创建工单 | 用户描述现场质量问题（带/不带图片），要求报事 | 调用 [create_ticket tool_call](工单创建HITL_tool定义.md) |
| 混合意图 | 同时涉及知识查询和报事 | 先执行知识查询，再根据用户追问决定是否创建工单 |
| 闲聊/超范围 | 与建筑施工质检无关的对话 | 礼貌告知超出范围 |

## 工具列表

| 工具名 | 类型 | 说明 |
|--------|------|------|
| queryTicket | MCP（stdio） | 只读查询工单信息，详见 [工单查询MCP定义](工单查询MCP定义.md) |
| create_ticket | Tool Call（HITL） | 创建工单（需用户确认），详见 [工单创建HITL_tool定义](工单创建HITL_tool定义.md) |
| consult_construction_knowledge | 外部 API | 知识查询子 Agent，详见 [知识查询子Agent说明](知识查询子Agent说明.md) |

## 开发框架

- **主 Agent**：LangChain `createAgent` + `useStream`（SSE 流式）
- **对话持久化**：LangGraph `PostgresSaver`（Supabase Transaction Pooler）
- **MCP 集成**：LangChain `MultiServerMCPClient`（stdio transport）
- **监控**：LangSmith

## 用户流程

### 流程 A：专业知识问答
用户提问 → 主Agent意图识别 → 调用知识子Agent → 整理回答用户

### 流程 B：工单信息查询
用户提问 → 主Agent意图识别 → 调用queryTicket MCP → 向用户汇报进度

### 流程 C：质检员报事创建工单
用户报事 → 主Agent识别报事参数 → create_ticket tool_call → 前端渲染创建卡片（含责任人选择）→ 用户确认提交 → 前端返回ticket_id → Agent告知创建完成

### 流程 D：知识 + 工单联动
用户提问 → 主Agent多模态理解 → 调用知识子Agent → 回答规范判定 → 用户追问"创建工单" → 主Agent整理上下文 → create_ticket tool_call → 前端确认提交 → Agent告知创建完成
